## التحقق

- npm test: اختبارات حساب أيام العمل، السنة الكبيسة، عبور السنة، أيام نهاية الأسبوع، تداخل الخصم، النسخ والاستعادة، والواجهة الفعلية بجميع ملفاتها.
- tests/database-restore.sql: تحقق فعلي من فشل الاستعادة دون تغيير البيانات، والاستعادة الصحيحة، وتوافق النسخ القديمة، وحماية الحساب المعطل. كل كتابات هذا الاختبار داخل BEGIN/ROLLBACK.
- فحص RLS وصلاحيات الدالة الجديدة على قاعدة البيانات المستخدمة، وفحص Supabase الأمني.
- بناء Cloudflare Worker باستخدام wrangler deploy --dry-run.
- GitHub Actions يعيد اختبارات Node وبناء Worker لكل push وpull request.

هذه اختبارات منطق وDOM وقاعدة بيانات، وليست اختبار لمس أو إشعارات على iPhone فعلي. لم تُعدّل كلمات المرور أو بيانات الإجازات القائمة أثناء إصلاح المصدر. الترحيل يضيف دالة استعادة ويحسّن حراسة الدوال القديمة دون نقل الجداول أو تغيير الأرصدة الحالية.

## حدود تحتاج تطويرًا محددًا

- لا يوجد اشتراك Realtime حاليًا؛ المزامنة ليست لحظية مستمرة بين الجهازين.
- انتهاء المرحّل يظهر كتنبيه؛ يجب تحديد سياسة استهلاكه وانتهاء غير المستخدم منه قبل تغيير الأرصدة تلقائيًا.
- إنشاء سجل «اعتماد/نشر» في قاعدة البيانات لا ينشر الكود ولا يثبت بصمة النسخة وحده؛ الربط الإلزامي بمدار وخط نشر الإصدار غير موجود لإجازاتي بعد.
- التطبيق لا يملك طابور عمليات Offline؛ بعد إغلاقه دون اتصال لا يوجد ضمان تحميل البيانات أو حفظ عمليات جديدة. الكاش هنا لملفات الواجهة وليس قاعدة بيانات محلية.
- ما زالت الواجهة تعتمد على سلسلة ترقيعات تاريخية؛ توحيدها إلى وحدات واضحة ضمن الإصدار الكبير أفضل من إعادة بنائها أثناء الإصلاحات.
